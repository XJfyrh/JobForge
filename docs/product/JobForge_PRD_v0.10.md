# JobForge PRD v0.10：S1-C 云端固定流程与正式执行器

- 日期：2026-09-16；状态：随 [PR #41](https://github.com/XJfyrh/JobForge/pull/41) 合并接受（`01177e9`），实施与真实云端验收另行报告。
- 基线：[PRD v0.7](JobForge_PRD_v0.7.md)、[v0.8](JobForge_PRD_v0.8.md)、[v0.9](JobForge_PRD_v0.9.md)。S1-B 已随 [PR #40](https://github.com/XJfyrh/JobForge/pull/40) 合并，提交 `f63300c`。
- 决策：[ADR-0018](../adr/0018-deepseek-fixed-flow-and-executor.md)。本增量不代替S2动态Agent、S3恢复对比、S4审批写入或S5保留集/观测/留存。

## 1. 行为

使用已安装Python SDK提交开发集工单，经真实控制HTTP/PG领取Run。正式Go Worker保持执行权，监管固定Python guardian及单step子进程，调用真实业务HTTP和本地固定embedding/pgvector，最后调用DeepSeek生成结构化、有证据的处理方案。方案等待审批，只有明确无动作才成功；本阶段不批准或写入业务工单。

采用合理固定流程作为后续Agent对比基线：读取工单和订单；确无订单时跳过无意义的物流补查，存在订单时补查物流；依据已取事实构造有界政策查询；将实际返回证据交给同一云端模型生成方案。不能把gold、预计算结论或case ID判定表交给执行器。该流程不声称模型自主选择工具，动态策略仍在S2。

## 3. 输出和数据

方案保留现有decision/action/summary/evidence_refs，并在新的注册策略下增加有界结构化结论、requested_fields、target_ticket_status及声明与来源关联。模型只生成结构化字段，summary及完整引用由固定代码忠实渲染，不能额外作业务承诺。target_ticket_status表示将来获批动作的建议目标（记录结论/无动作保留当前状态，补充信息为awaiting_information，升级为escalated），不表示本阶段已经更新。源码schema在实现PR交付。运行校验保证结构与引用真实来源，评分器额外检查证据是否支撑具体判断；两者不能混为一个“引用正确率”，也不能在运行时用gold改正模型答案。

开发数据是合成事实，当前draft标签需在首次云端评分前完成独立审查和冻结。Agent审查必须标明为Agent审查，不能记录为人类逐例评审。如政策文本调整，创建新语料/政策/索引版本、重新运行真实embedding与20查询，保留S1-A历史未命中与结果。

独立审查发现P01对注释必须有结构化佐证的概述，与P05/P06允许使用carrier注释识别事件key及明确更正存在歧义。新政策限定carrier来源注释可提供事件关联/更正的业务陈述，并保留来源；任何注释中的指令都不能改变授权、模型、工具、租户或规则。客户指令不能被解释为carrier更正。不能通过编辑gold掩盖模型错误。

## 4. 保留边界

真实外部请求发出后，本地取消不保证供应商停止或退款。模型别名与价格快照不是不可变服务端锁定；成本上界依赖供应商遵守已核对配置和计量合同。unknown全额hold及异常冻结继续有效。

固定流程质量是开发基线，不是泛化能力结论。整体最低保留集门槛、Agent比较、成本恢复对比、审批写入及可观测/保留验收继续按v0.7及路线执行。历史W4失败、AT-25跳过、远程模型和生产留存未验收仍保留；真实云端通过时新增范围明确的证据，不改写历史。
