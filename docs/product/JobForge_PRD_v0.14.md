# JobForge PRD v0.14：S1 收尾新批次的累计费用授权

- 日期：2026-09-17；状态：**Accepted（随 [PR #53](https://github.com/XJfyrh/JobForge/pull/53) 独立审查通过并合并时生效）；实施与真实验收另行记录**。
- 基线：[PRD v0.10](JobForge_PRD_v0.10.md)、[v0.13](JobForge_PRD_v0.13.md)；对应 [ADR-0022](../adr/0022-s1-closeout-cumulative-authorization.md)。
- 本增量仅落实维护者在原首批停止后明确给出的 S1 收尾授权；不恢复原批次，不改变旧报告、Run、账本、hold、attempted 标记或验收成绩。

## 1. 新授权与历史边界

维护者于 2026-09-17 明确授权：修复已知问题后，在正式部署上开展新的 S1 真实 DeepSeek 验收；**本次授权下全部新增云端费用累计上限为 5 CNY（5,000,000 microyuan）**，包含重验及唯一协议纠正等实际调用。更换 batch 不重新获得 5 元，不充值、增资或切换供应商。该授权是新的维护者决定，不是 ADR-0021 首批的续跑入口。

原 batch `a4ad1772-3af9-4985-8040-5e3ed6aba1a9` 永远不再 launch。所有旧身份、失败、未尝试、已知费用、未知费用及原始证据保留；只读导出和原身份已有的窄晚到确认权限仍按旧合同处理。不得解冻、清零、删标记、覆盖 profile 或把旧 Run 迁入新批次。历史费用与本次新增费用分栏报告，不能把 unknown/full hold 当作零费。

新批次使用新的 batch、专属 Worker、profile、账户、业务键及幂等键，并绑定修复后的实际源码、prompt/schema 与镜像摘要。新身份代表同一冻结 40 案的一次完整新验收，不代替、补写或拼接旧成绩；业务数据、政策、索引及评分规则保持冻结，不为提高成绩改 gold 或打开保留集。

## 2. 启动与累计额度

每次准备新批次前，先读取旧账本及部署事实，确认全部前批 launcher、driver、Worker 和受监管旧组已停止、无仍可能派发的进程，核对在途控制请求及原调用必要的持久确认。只看到退出标记、零余额变化或 disabled 配置不足以证明这些条件成立；不能通过新 batch 绕过缺失的必要确认。无法安全核算的费用或无法证明停止的外部环境故障阻止收费。

对本次授权下已启动的新批次集合，按每个 batch 账户一次聚合，不将同一调用的 family/tenant/batch 金额重复相加：

```text
剩余额度 = 5,000,000 − 本次新增批次累计 known_cost_microyuan
                      − 本次新增批次累计 held_cost_microyuan
```

新 batch 的持久费用上限不得高于该剩余额度；低于下一物理调用所需保守预留时不启动收费。保留 profile/family/tenant 的原固定上限，由更小的共享 batch 上限约束实际累计暴露。旧首批不属于这项新增 5 元授权，其全部费用及未知项另列并先核算；已有未知或在途事实不能因分栏而忽略。

复用原账本、只读 inspect、部署记录与批次停发机制；只允许在前批完全停止后串行准备下一批。启动记录追加列明授权、所有前批 ID/核对时点、known/held/剩余额度、本批上限及停止和确认凭据，不引入通用预算平台、自动续跑或后台恢复器。

每个新批次仍固定 **6 小时**，一个 Worker、一个案例串行，Worker/tenant/profile 容量均为 **1**，north/south 各 20 案共享一个 batch。原次数/token/单次预留、唯一纠正、持久 chat guard、unknown hold、冻结和退出屏障全部保留。停止后仅导出原事实；再次运行必须重新完成本节核对并使用新批次，不能重启已 attempted 的批次。

## 3. 收尾验收

沿用 C-01～C-08 和 L-01～L-08 的实现与验收要求；本增量仅将首批限定扩展为上述有限累计授权下的新批次。

| 要求 | 必须保留的证据 |
|---|---|
| 新批次准入 | 旧派发者实际停止、必要持久确认完整、累计 known/held 与剩余额度、独立新身份及部署摘要 |
| 固定 40 案完整执行 | 经正式 SDK→控制面→Worker→真实工具→DeepSeek 链路执行；成功和明确业务失败如实导出，中断、未尝试或缺关键证据不计完成 |
| 业务与安全分开 | 全部 40 案为分母，分别报告结构、来源、业务与安全；安全硬失败为 0 且证据完整；不新增开发集正确率门槛 |
| 工程与复现 | 最终差异独立审查、适用强制 CI 通过；干净环境必要复现步骤验证，不为复现再次收费跑完整 40 案 |

`awaiting_approval` 仍只表示方案完成并释放租约，不表示批准、业务写入或工单已解决。本次闭合 S1 后停止；S2～S5、历史 W4 失败、AT-25 跳过及生产长期留存限制保持单列。合同接受、确定性检查或 scorer 退出 0 都不代表真实 S1 验收通过。
