## 依据与范围

第二次正式 Agent 为 10/20 正确、10/20 完整案例证据。零调用重建确认 87 次请求绑定、20 案事实与政策投影、事件顺序及 UTC 秒差均一致。错误集中在冲突必要条件、严格较后纠正、政策取证未齐和正时间差被判为准时。新提示的有效性需要实际模型验证。

最小候选只调整模型调查和提交前核对提示，复用原有事实投影、UTC 秒差、工具、结构/来源校验、预算和执行器。Python 不执行政策谓词、不读取 gold、不替模型生成主张或修正方案。旧正式集只用于诊断；正式质量仍须由新冻结后的未见集证明。

## 候选与兼容

新增 Agent schema 9 / `support-agent-prompt-v3` / `support_agent_v3.py`，通过部署 manifest 2 显式选择。沿用 schema 7 的原事实、导航、完整内外层合同和限制。schema 1–8 及原 prompt 源文件字节保持；新 prompt 的源码摘要和完整运行包摘要重新绑定。

提交前提示要求模型按实际取回政策核对每个必要条件：

1. 冲突必须取到定义段落，不能把 correction 或优先级段落视为完整冲突定义。完整 source key、不同状态、最新同一 UTC 时刻、精确订单/物流状态条件分别核对；相似标签或相同后缀不代替定义。
2. 纠正须由本物流内实际较后事件的事实 note 明确指向原事件；时间相同、早于原事件、引用本返回物流不存在的事件和普通后续扫描都不满足。保留原事件，模型自行确定活动时间线。
3. 时效使用原秒差：已送达看所选有效 delivered 的 event-minus-promise，未送达看 observed-minus-promise。特殊工单状态只影响动作；不得把 informational_only 推断成准时。
4. 在上述条件否定当前假设后继续调查，按仍未解决的问题选择异常、时效等政策检索。先核对事实和政策，再输出原六字段方案，不增加推理文本或额外输出字段。

新增 Fixed schema 10 只接受新包身份，复用原 Fixed 图、提示、投影和校验。两策略保持同一模型、thinking disabled、temperature 0、1024 输出 token、工具/数据/family 限额。HTTP、SDK、Proto、数据库、状态与错误码无变化；生产 registry 仍仅两个 adapter。

## 冻结与未见集

新增 `support-s5-2026-10-08-v3` 包身份。开发门保持正确方案和完整案例证据均至少 36/40、硬失败为 0；独立接受后才能冻结。原 Fixed 开发证据仅在源码差异确认行为与模型配置不变且独立接受后复用；否则重新执行 Fixed 开发回归并计入原累计费用。

冻结显式绑定两个已见正式包 manifest hash 及其场景家族。新 20 案在冻结后创建，对原开发集和正式 v1/v2 都做独立场景/模板新颖性审查。开发40、正式20登记分别验证，未知 dataset 拒绝。已见诊断入口可读原 v1/v2 的原冻结证据，恒为 `thresholds_met=false`；历史重评分不改写原报告。

恢复工具新增明确版本的 S5 v3 绑定，保留原 11 项故障/对照清单和原配置。只有正式 Agent 达到正确至少 16/20、完整证据至少 18/20、两策略四类硬失败为 0 后，才启动恢复与同候选演示。

## 有限运行计划

S5 总费用继续为 20,000,000 microyuan，每批最多 4,000,000 microyuan、6 小时、串行。停止时累计 269 Runs、895 chat、known 2,874,643 microyuan、held 0；新身份不重置累计。

维护者于2026-10-08明确要求不遵守或设置费用之外的预算。因此，原300 Runs / 1,600 chat及后续数量扩额提议不再是执行授权上限，不另设阶段级Run/chat/token预算。下面的案数是验收工作量，不是预算；每次生产Run已有的协议、超时和防无界循环限制继续属于产品合同。持久batch所需计数字段按登记名单和原family合同生成，不再人为缩小到400次chat。

| 顺序 | 验收案数 | 批次费用上限（microyuan） |
|---|---:|---:|
| Agent 开发回归 | 40 | 3,400,000 |
| 新正式 Agent | 20 | 3,400,000 |
| 同包正式 Fixed | 20 | 3,400,000 |
| 原恢复对照 | 11 | 3,000,000 |
| 实模演示 | 1 | 2,200,000 |

每批实际 cap 还受启动前累计 known+held 后的余量限制。第一批前记录当天模型/价格/账户只读核验、磁盘余量、源码/构建/profile 身份、全部旧进程回收与持久账本。C 盘低于 15 GiB 或快速下降即停；unknown、在途无法闭合、安全硬失败和身份冲突继续沿用原停批规则。

开发前10案先审语义；已不可能达到36/40或出现系统性格式失败时停止，其余仍在原40分母。正式普通质量失败仍完成同包 Fixed 对照，再停止恢复/演示。各阶段执行前形成具体有限 manifest 并取得独立放行。

## 验证与退出

独立审查本诊断和方案后才实施。免费验证包含原 schema/prompt 字节兼容、版本混用拒绝、事实及来源隔离、检索导航、20/40数量路由、已见诊断不达标、新包同时绑定两个已见包，以及安装 SDK、真实 PG/race、固定 Linux 进程和生产镜像边界。按实际改动运行，未变化且有效的检查证据复用。
