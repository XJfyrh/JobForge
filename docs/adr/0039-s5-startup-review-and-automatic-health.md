# ADR-0039：S5 一次启动审查与自动健康检查

- 日期：2026-10-15；状态：Accepted（维护者已批准工作流改造；具体收费实验仍须启动审查）。
- 对后续新批次，取代 ADR-0034/0036 的固定第 10 案人工暂停和“模型引用/定义闭合缺口立即停发”规则，合并 ADR-0038 的代码、配置和收费 manifest 审查。历史 ADR 正文、原始证据及已停止批次保持原样。

## 决策

一次授权明确范围，小步验证，自动检查，异常才打断。不建设管理平台；除金额外不增加阶段预算，预先登记的有限名单与既有单 Run 次数、期限和逐调用预留合同继续有效。

每轮回答一个问题：提出假设 → 最小诊断 → 有效才实现 → 完整回归。诊断优先用已见案例，提前确定名单并保留全部结果，不择优报告。收益未证明前不扩展生产协议、恢复或公开 schema；提示词仅做必要的候选版本管理，公开契约、可靠性或权限改变才另写 ADR。已实现的 v8 直接推进开发回归，不补诊断。

维护者批准具体名单、候选、模型、执行权限和金额；独立审查核对实际实现、免费验证及同一份 manifest。两项意见组成一次启动审查，均绑定 manifest 原始字节和授权/审查证据。批准工作流方案不构成收费授权。批次获准后自动完成既定名单，每案导出后自动健康检查，第 10 案与其他案相同，不再请求“继续”。改变已批准名单、候选、模型、金额或执行权限，只审查变化部分并重新绑定完整 manifest；不能沿用旧摘要。

| 观察 | 自动处理 |
|---|---|
| unknown、身份/来源绑定异常、未经批准写入、实际额度突破 | 立即停发，保留原始证据和 hold |
| 费用不足以覆盖下一次完整预留 | 停止后续提交；逐物理调用仍由 PostgreSQL Reserve 裁定 |
| 普通错答、政策齐全但引用/定义证据不完整、一次可审计格式失败 | 记失败，继续名单 |
| 正确或完整证据的可达上界低于门槛 | 停止后续提交，原分母保留 |
| 同一协议失败连续两案，或首三案中出现两次 | 预先定义的系统性故障，停止后续提交 |
| 政策包实际缺段、重复或跨快照/索引/来源绑定 | 机制异常；首次模型调用前沿用生产失败关闭，宿主检查同样停发 |
| 原因不清楚 | 保存结果，批后集中分析，不自动开发新版本 |

开发门槛保持正确至少 36/40、完整证据至少 38/40、硬失败零；正式仍为 16/20、18/20、硬失败零，并要求未见集与既有冻结流程。004/018/DEV-020 等已见失败完整保留在回归名单与报告中，普通质量失败不再单独触发即时停发。不自动重试质量失败、不补样、不更换分母、不重开旧批次。

## 实现边界

配置记录候选源、完整名单、固定镜像、数据库清单及费用；共享现有 Go 准备、SDK 单次提交、导出、组装和严格评分。宿主程序生成文件哈希、版本一致性、逐案决策、累计费用及结果报告。gold 与评分只留宿主机，容器只交换导出身份和哈希；宿主失联不会自动放行。生产 registry、协议和执行权不变。

当前共享入口限定为 v8 schema16/17 的完整开发 40 案；固定输入诊断沿用已有诊断工具，正式冻结沿用已有冻结工具。构建、业务数据和私有凭据准备仍使用现有入口，不增加通用基础设施编排。

沿用每批至多 ¥4、S5 累计至多 ¥28。配置可收紧金额；提高上限须另获授权并修订合同。启动时刷新显式历史数据库清单，不能漏掉已停止批次或把 unknown/不可读账本记零。新批次必须新身份、新目录、新库；单次启动锁、原 attempted 锁和 PostgreSQL 许可共同阻止重开。当前价格下调查/终裁完整预留为 2,105,344 / 2,228,224 microyuan；从登记的价格和上限重新计算。案间健康检查保守要求足以覆盖较大的一次完整预留，不用平均实际费用替代。

同一 S5 的启动锁旁维护一份当前数据库清单和费用快照；发送前登记新库，清理与闭账后刷新。旧配置遗漏随后启动的批次时拒绝放行，历史库身份及已确认 known 不得下降；full hold 合法结算为较小 observed usage 可以下降。清单属于当前执行状态，不是管理平台。失联启动也按本轮预登记容器逐个核验、停机；任一清理或闭账未确认则保留锁，不记录工程完成。

批后只做一次结果审阅并决定下一步；修复只复核问题、影响和新增差异。工程完成与模型质量达标分开记录，独立工程改动可交付，S5 总体验收仍受原质量门槛约束。当前已有提交不重做历史拆分，后续改动保持小而独立。

## 验证

免费测试应覆盖一次格式失败继续、缺段/跨绑定停止、不可达门槛停止、完整预留等号边界、启动审查摘要与证据绑定、第 10 案自动放行、篡改回执拒绝、旧身份不可重开、账本不可读失败关闭、镜像无宿主守卫/gold。按现有精简 CI 选择器验证，不因工作流改造重复无新风险的已通过全量验证。实际结果记录在当前状态页。
