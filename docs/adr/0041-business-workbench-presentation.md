# ADR-0041：业务工作台与部署处理方式

- 日期：2026-10-16；状态：Accepted。
- 增补 [PRD v0.19](../product/JobForge_PRD_v0.19.md) 与 [ADR-0027](0027-s5-observability-and-data-lifecycle.md) 的页面展示，不改变执行、审批、回执、费用与留存语义。

## 决策

将已选定的工作台原型应用到 Go 托管的静态 HTML/CSS/JavaScript。业务页面围绕任务、事实依据、原方案、批准影响和实际更新结果组织；取消同页的执行与账本技术详情。步骤接口仅用于取出原方案和实际业务来源，界面不呈现原始 JSON、hash、profile、attempt、Trace 或调用账本。未知结果、已结束任务及费用暂占继续分别展示。

页面不增加角色切换器。身份仍来自 `/v2/identity`；切换身份必须退出并使用另一凭据。凭据只在内存保存，退出、401 与身份切换清空页面并使旧响应失效。审批确认展示原方案及目标工单标记，POST 仍绑定服务端保存的 proposal hash 和稳定操作键。取消不撤回已有业务效果，核对只读取已有回执。

新建任务的处理方式由部署可选字段 `ui_options` 提供，每项绑定 `tenant_id`、业务名称 `name`、已登记 `profile_id` 与该租户的 `budget_batch_id`。未配置时为空；停用 profile 不出现在选择中。配置仅提供展示和请求参数，不启用 profile、不创建预算、不代替原提交准入。

新增同源 `GET /v2/ui-options`：仅 operator 可读取当前受信租户的 `items`，每项为 `name/profile_id/budget_batch_id`；拒绝查询参数，reader/approver 返回 403，未认证返回 401。页面只显示业务名称，仍通过既有 `POST /v2/runs` 提交。SDK 与既有调用者的接口及配置兼容；未配置页面处理方式时，既有 API 提交仍按原合同工作。

统计、筛选和搜索明确限定为已加载列表，不假装全库总数。任务短编号仅作展示，完整编号可以查询和复制；不建立新的持久别名。事实片段必须来自该方案引用的原始来源与指针，无法解析时明确告知，不以附近片段或演示文案代替。

## 边界与验证

本次是业务展示分离，没有新增审计角色，也没有撤销现行 API/SDK 的技术查询权限。部署凭据和服务端角色仍是授权边界，隐藏页面内容不构成字段级访问控制。若后续要求对现有 API 调用者限制技术字段，需另行定义兼容契约。

背景与图标随二进制嵌入，无 CDN；中文字体使用覆盖固定界面文案的 WOFF2 子集，其余业务内容回退系统字体。CSP 仅增加同源字体许可，继续禁止内联脚本、跨源连接与嵌入。Node 22 仅用于无依赖的界面投影测试，生产无需 Node。

验证覆盖配置隔离与空配置、停用方式、静态资源白名单、401/身份切换、审批确认、未知结果与迟到回执、准确来源解析、桌面及移动布局。没有数据库迁移，不运行模型或新增收费批次。
