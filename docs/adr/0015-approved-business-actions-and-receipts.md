# ADR-0015：审批、受控写入与业务回执

- 状态：Proposed。
- 日期：2026-09-16。
- 关联：[PRD v0.7](../product/JobForge_PRD_v0.7.md)、[ADR-0013](0013-durable-agent-run-and-step-commit.md)。
- 拟补充：ADR-0009/0011 的业务幂等；新版本增加明确人工授权及回执不确定性。

## 决策

1. 模型只有三个只读工具，最终方案不直接携带写权限。一个 Run 最多一个审批点，审批针对不可变方案和一个固定业务动作。
2. 审批记录绑定 tenant、run_id、proposal_hash、审批者、权限、expiry 和工单/订单/物流/政策版本。进入等待与释放 lease 原子提交；批准与 ready 原子提交。重复相同请求幂等，冲突决定/版本拒绝。
3. 写入前在有效租约下请求派发授权。授权与取消锁同一 Run 行，固定 operation_id、参数 hash 和审批引用；首次授权后的操作内容不可改写。
4. 业务服务在事务中先查 tenant+operation_id。相同已接受动作直接返回首次回执，异内容 CONFLICT；首次写入才校验批准和所有前置版本，原子变更业务对象及保存回执。工单更新产生的新版本不使同一已应用操作失去幂等性。
5. 业务服务使用受信内部身份校验授权，不能接受模型提供的 approved=true 或任意 approval_id 作证。授权验证覆盖精确内容、目标租户、期限和版本；具体签名/内部鉴权方式在 S1/S4 源协议中固定，不引入公网匿名写入口。
6. 本地业务服务掌握可事务核验的决策依赖版本。只读工具统一使用不可变snapshot_id，物流使用包含新增事件的聚合版本；任何当前版本变化导致 ACTION_CONFLICT，不继续旧方案。首轮不自动循环重新审批。
7. 未收到回执不能断言没有写入。正常恢复使用相同 operation_id 查询或重发相同动作；接收端去重。旧 Worker 的回执不能越过新的 lease 推进 Run。
8. 派发授权先提交时，在途外部写入可能在取消后发生；不承诺跨系统全局 fencing 或撤销。取消后的回执核对仅为授权、有界的只读操作，可更新动作效果视图，不能重开 Run、改变终态或再次发起写入。未知保持 unknown。
9. 人工 retry 的新 Run 继承业务请求/操作身份及费用批次，先核对已有回执。已授权操作的内容不能通过新 Run 换成另一动作，真正新业务意图需新请求键并重新审批。
10. 终态 Run/checkpoint 保存7日，人工 retry 限原请求创建后7日；业务身份/回执至少30日且覆盖全部有效请求期。到期旧操作拒绝；清理记录不能恢复旧操作的写权限。
11. 人工新 Run 若继承到已派发授权且回执未知，仅查询并以 ACTION_OUTCOME_UNKNOWN 结束，不重发、续签或复用旧审批写入。只有原非终态 Run 正常恢复可在原授权有效期内重发完全相同动作。授权前失败可重新核查，已应用动作复用回执。
12. 审批/许可截止为方案提交后1小时与Run deadline的较早者；批准、排队和恢复不延长。授权过期只查既有回执，禁止首次执行。批准请求在鉴权后先识别已接受操作幂等键，再对新请求检查awaiting_approval与期限。

## 业务结果与边界

approved 表示许可，applied 表示接收端确认动作已经提交。rejected/no_action 是正常业务结束；基础设施错误、版本冲突和未知效果不是“已经处理成功”。工单写入仅记录结论、待补充或升级人工跟进，不声称客户问题已解决。

效果视图允许在 Run 终态后补齐回执，但 Run 终态与首次结果不被覆盖。效果视图和业务回执有独立版本及来源审计，UI 必须区分 Run cancelled 与效果 applied/unknown。

## 数据与替代方案

需要 approvals、business_requests/action_authorizations、action_receipt_views；业务接收端有独立唯一键及回执表。相同数据库实例不使两次 HTTP/事务自动获得原子提交，故障窗口仍按跨边界协议验证。

- 先写入后让用户确认：授权顺序错误，不采用。
- 长期占用 Worker 等待用户：资源浪费且无法证明重启恢复，不采用。
- 重试时换一个操作 ID：可能重复业务效果，不采用。
- 取消后主动重发未知写入以查询效果：可能首次产生新效果，不采用。

## 验证

重复/过期/越权审批，批准后物流等依赖变更，写入后回执丢失，Go/Python 进程退出，派发授权与取消竞争，旧 Worker 晚到，人工新 Run 复用回执，操作同 ID 异内容，清理边界与过窗重试。测试使用真实 HTTP 业务服务和 PostgreSQL，而非预录回执。
