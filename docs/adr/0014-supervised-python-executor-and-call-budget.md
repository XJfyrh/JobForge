# ADR-0014：受监管 Python 执行器与调用额度

- 状态：Proposed；执行器选择以S0进程试验为依据，云端模型的真实接入与业务验收单独记录。
- 日期：2026-09-16。
- 关联：[PRD v0.7](../product/JobForge_PRD_v0.7.md)、[ADR-0013](0013-durable-agent-run-and-step-commit.md)。
- 拟取代范围：ADR-0011 在新版本中纯 Go 模型 Handler、无 Python 子进程的选择。

## 上下文与选择

Python 负责模型协议、结构化校验、检索和业务适配；Go 负责执行权与持久进度。引入 Python 的收益必须覆盖双工具链和生命周期成本，因此先做真实进程试验。纯 Go、纯 Python 自研 PG 运行时及采用成熟框架均已比较，不以当前代码语言作为唯一理由。

2026-09-16评审调整：维护者明确模型不应以本地为主线。本版采用单一云端主chat支持Agent开发、评测和演示，本地chat仅为可选适配。作品集优先证明真实业务工具、持久步骤、审批、故障恢复和调用治理；本机CPU推理能力不作为工程推进条件。两个本地候选的失败保留为试验事实，不阻挡契约PR或S1，也不作为云端能力的证据。本ADR仍在评审，本次修订不修改已接受决策的历史内容。

## 执行器契约

1. Go Worker 是唯一 lease 持有者，控制面是唯一状态和预算裁决者。Python 只执行已指定的单个模型/只读工具步骤，不轮询队列、不续租、不写控制表、不后台恢复。
2. 固定入口、预注册操作、有界版本化 stdin/stdout 帧。请求携带 request_id/step_id、剩余 deadline、profile、已授权资源与 TraceContext；响应只含相同请求身份、结构化结果/固定错误和计量。不得把字符串 payload 拼成 shell、模块路径或工具定义。
3. 一个活跃 Run 最多一个受监管执行器进程组；组内 guardian 保持控制通道响应，最多一个固定 step 子进程执行阻塞业务。guardian 不持久调度，是父进程生命周期的实现细节。
4. 正常取消/超时由 Go 发送终止并在宽限期后 Kill 整个组、Wait 回收。父进程 SIGKILL 后 guardian 通过控制通道 EOF 退出并清理执行组。容器使用 init 回收孤儿，不能把 init 当作主动终止保证。guardian 自身死亡也必须在试验中验证无长期存活步骤进程。
5. Linux 容器为运行环境，Windows 通过同一 Compose 启动；不声称原生 Windows Worker 或逃逸进程组的任意子进程受控。只运行项目自己的固定能力。
6. stdout 是协议专用通道；超大帧、额外输出、请求身份错配、错误版本、早退均明确失败并回收执行器。stderr 有界且只允许脱敏诊断。
7. 模型 HTTP 取消只承诺停止本地等待和后续处理；不能保证远端计算停止或退款。所有调用都带剩余 deadline，不隐藏重试。

## 调用额度与模型 profile

调用预留在网络发送前完成。控制面锁定 Run/步骤及批次计数，校验有效 lease、预算和调用 ID，原子增加相应预留；同一预留重复请求只返回原记录，不能再次许可一个新物理调用。

physical_call_id 对应一次可能发出的网络请求，不作为允许模型端重发的幂等保证。客户端无法确认是否已发送时，将该预留视作 unknown；再次发请求要申请新的 ID 并占用新额度。模型响应/usage 已知则结算，未知不自动释放预算。

physical_call_id 必须穿透执行器 request_id；同进程重复帧只返回既有记录或明确拒绝，不再次发起网络调用。物理请求次数在授权后不退回，known usage 只结算 token/费用。已派发调用的计量可在 lease/Run 结束后按调用身份幂等补齐，但不推进 Run 或改变终态。当前有效执行器不并行调度，不代表故障后远端旧推理和新请求不会重叠。

Run、tenant、验收批次有独立上限，锁顺序固定。manual retry 继承批次，已完成步骤/已有回执查询先于新增推理额度检查。收费额度 B、价格版本、最大输入/输出 token 和收费项必须可保守界定；凭据和费用未选定时禁止收费探测。

云端候选以工具调用、结构化输出、可固定版本和可界定计费为筛选条件，最终接受仍以实际接入及业务试验为准。profile锁定供应商、地域、受信部署配置中的HTTPS endpoint、模型快照或可取得的版本标识、上下文参数、工具Schema及价格版本；不要求不存在的云端权重digest。凭据只由部署注入，endpoint和凭据不能由payload或模型指定；供应商响应经Python薄适配转换，不进入Go状态机。首轮不实现多供应商路由或自动切换。

S0冻结候选与费用方案即可独立评审；最小持久调用账本、费用预留与单一云端适配在S1并行实现，后续复用到S2。缺少凭据或预算只阻止收费请求，不能构成适配器、账本或业务工具的开发前置。收费探测同样先有额度约束；真实云端工具循环和S2验收不可由确定性替身替代。本地chat不再追加候选或作为准入门槛。

RAG初选pgvector小语料精确检索；embedding与chat独立选型，可使用本地真实embedding，也可采用云端。embedding模型身份、向量维度和索引profile必须一致，tenant与政策版本过滤不可由模型覆盖；收费embedding使用同一调用治理。关键依赖引入时固定版本、许可与复现命令。

## 验证与后果

S0 探针覆盖正常执行、错协议、超大输出、timeout/cancel、Go SIGKILL、guardian 崩溃和资源回收；真实模型探针覆盖工具参数、反馈利用与最终结构化结果。fixture 工具只验证协议，不能验收真实工单业务。

生产接入另需真实Go/Python契约、跨Worker额度竞争、unknown/人工retry、TraceContext、输入输出上限和进程故障测试。云端实际调用未运行时保持未验收，不能把候选官方能力当作项目通过证据。进程探针也不等于完整执行器验收。
