# ADR-0028：售后 Agent 证据导航的独立候选版本

- 日期：2026-10-07；状态：**Accepted，独立规划审查接受，随本 PR 合并生效**。
- 增补 [ADR-0027](0027-s5-observability-and-data-lifecycle.md) 的公平比较版本及 [PRD v0.19](../product/JobForge_PRD_v0.19.md) 的冻结验收流程。历史 schema 1–6、提示词、原评测结果和政策正文保留。

首轮正式 Agent 为 12/20 正确、12/20 完整证据，未达 16/18 门槛。失误包括引用无关政策、漏掉独立必要事实、引用旧事件及重复已完成查询。允许一次显式候选修正；首轮 20 案已成为已见诊断集，不能再次计为未见验收。

新增 Agent schema 7，绑定 `support-agent-prompt-v2` 与 `support_agent_v2.py` 的真实源码摘要；继承 schema 6 的审批、原确认恢复、模型及全部家庭额度。新 Fixed schema 8 保持 schema 5 的提示词、事实投影、工具图及额度行为，用于新数据身份的对照。两个版本允许原开发集、已见首轮正式集和 `support-s5-2026-10-07-v2`。

部署 manifest schema 2 的每个 profile 显式携带 `prompt_version`。Go 核验它与不可变 profile 的 program 一致，Python 只选择已安装的固定实现；Agent v2 仍使用 `support-agent-v1` 身份，生产 registry 仍为原两个 adapter。历史 manifest 1 不接受新增选择字段，新 profile 不得搭配旧 manifest。execute_step、Go 调度及重复拒绝保持原合同。

新提示词将规范定义、纠错、状态与优先级分为导航角色，只展示实际取回的段落别名及已提交工具的规范参数。事实与时间差仍来自接受的 T/E1/E2；静态引用导航不推断适用规则、不生成结论或必需 claim，不调用离线 scorer/gold，也不自动获取政策。模型决定全部后续工具和最终方案，一次纠错、八次工具及十二次聊天上限保持。

`prepare-support --batch-chat-limit` 可缩小持久共享 batch 的聊天上限，范围为 1 到登记案数乘十二；默认 0 保留既有生成结果。租户及家庭上限不变，生成摘要绑定该限制。跨批次累计仍包含所有原失败、known/held 与在途调用，沿用原 240 Runs、1,200 chat、¥20 授权。

新候选经免费检查、Agent 40 案开发回归和独立审查后重新冻结。Fixed 开发证据可在源码差异及回归证明行为不变后复用，原报告与构建身份不重写。新正式 20 案须在新冻结后创建，并对原开发 40 案及首轮正式 20 案作实质场景/模板新颖性审查；冻结和新包同时绑定首轮 manifest 摘要。评分真值、覆盖规则与门槛不变；已见诊断报告显式标记，不能通过未见验收。

恢复工具新增 plan schema 2 的 S5 路径，绑定 schema 7、相同候选提示词及原十一项故障/对照清单，停止于方案保存后待审批或原 no_action 终态，不批准业务写入。旧 plan schema 1/S3 报告语义保留。随后实际录制的演示使用同一候选，审批与唯一回执另行验证。

验证版本混用拒绝、事实投影及未取回引用隔离、已完成查询导航、共享额度限制、真实 PostgreSQL/race 与安装运行时，最新 head 的八项 CI 全部通过后才能发布。首次正式失败和后续费用证据持续保留；新提示词的质量由新未见集决定。
