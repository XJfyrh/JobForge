# ADR-0031：S5 固定输入裁决对照

- 日期：2026-10-11；状态：Accepted（独立设计审查接受；实现与收费放行另行核验）。维护者已批准实验方案。
- 增补 ADR-0030 的已见诊断；不改变历史候选、政策、gold、生产 profile 或正式验收门槛。

## 选择

已见 v3 正式 20 案作为固定诊断集，重建最终裁决前的原始输入并核验全部 103 次请求 hash。A 为原 v3 提示和已检索政策，B 仅开启 thinking high，C 仅增加同版本完整政策，D 仅改为精简且条件一致的提示。各组共同增加 final-only 诊断协议，各案各组重复 3 次，按轮次轮换组顺序。A 不是生产 Agent 端到端重跑；拒绝、非最终输出、截断、超时和未完成保留在分母。

四组统一使用 16,384 输出 token 容量，避免 B 独占更大容量；与历史 1,024 上限的成绩不作单因素比较。固定 DeepSeek Flash、非流式 JSON、单物理请求、无自动重试，B 为 thinking high，其余非思考 temperature 0。响应上限 1 MiB、最终 JSON 16 KiB、HTTP 超时 180 秒属于诊断协议边界，不是阶段预算。thinking 的 completion token 包含推理开销，只计一次；缺失或矛盾 usage 保留 full hold。模型及费率在执行当天重新核验并冻结。

## 隔离与账本

`tools/support_diagnosis` 中 Python 仅准备输入、只读元数据和离线评分；Go 命令拥有付费发送权。工具不进入生产镜像，不新增生产 adapter、Run、审批或写业务的能力。C 的新增段落保留政策正文 hash 和 `diagnostic-policy` 来源，不伪造业务检索记录。gold 不写入发送包，离线评分沿用原谓词与语义锚。

复用现有 PostgreSQL `budget_accounts`、`CreateBudget` 以及 `ReserveAccount`、`SettleAccount`、`UsageCost`，新增隔离诊断库的 versioned migration 和诊断调用持久层；不称其为完整生产调用账本。没有调度器、lease、恢复或重试引擎。唯一实验身份绑定精确库名、库内持久 UUID、manifest、请求正文、执行顺序、源码和费率摘要，重复启动不重新发送已预留 trial。离线评分使用只读 PG 导出核对 manifest、trial、request/response/report hash、状态与 usage，不以本地文件名作为调用事实。

Go 持有整个诊断库共同固定键的 session advisory lock；取锁后检查所有 batch 的 reserved/unknown/anomaly，任何遗留阻止跨批发送。预留事务锁定 batch 账户并原子增加 hold、插入唯一 trial；提交明确成功后才允许一次 HTTPS POST。网络固定官方 origin/path、拒绝重定向、关闭连接复用以避免隐式重发。结算在事务中核验原预留和首报告，完整可信 usage 即使答案错误或 finish_reason=length 也结算。unknown、身份/模式不符、超界、报告冲突或未闭合预留停止整个实验并保留费用证据。原始响应只存仓库外，普通日志不含正文、推理或凭据。

S5 总额仍为 20,000,000 microyuan。首次启动只读刷新所有旧批账本并确认付费入口停止，冻结既有 known+held；新诊断库累计 batch known+held 加入同一总额。单批费用上限不超过 4,000,000 microyuan 和累计剩余金额；不足以承担下一次保守预留时不发送。跨批只在上一批无在途/unknown 后继续，绝不抹除旧消费。240 是初次实验名单，不是阶段数量预算，不增加 Run/chat/token/工期预算。

## 结果与后续

报告完整方案、结论、行动、全部主张及必要证据覆盖、逐案修复/退化、3 轮稳定性、known/held、调用数与耗时。新增政策组来源指标显式区别于真实检索。每轮均改善完整正确数且不稳定损害原成功案例的改动才优先进入端到端验证；不选最佳重试，不把诊断结果计入正式门槛。

先交付对照结果与推荐；仅有证据支持的最小候选进入真实 Agent 回归。40 案开发的 36/40 双门槛、冻结后的新 20 案 16/20 与 18/20 门槛及四类安全硬失败为零保持。正式通过后才能恢复对照和演示。政策含义变化另提版本化决策，不修 gold 帮助本轮过关。

## 验证

免费检查覆盖原请求重建、组间单因素差异、完整政策来源隔离、无 gold 发送、评分正反例，以及真实 PG 的并发预留、重复 trial、未知留 hold、结算重放与冲突、超额和跨批累计。生产代码及历史输入不变；新命令和事务通过 race，当前适用 CI 按测试指南执行。具体执行身份、独立审查和收费前检查保存在仓库外证据目录。
