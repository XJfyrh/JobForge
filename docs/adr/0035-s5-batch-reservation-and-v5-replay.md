# ADR-0035：S5 批次预留上限与 v5 终裁回放

- 状态：Accepted（维护者批准费用修订；具体收费 manifest 仍需独立放行）
- 日期：2026-10-13
- 决策者：项目维护者
- 取代：[ADR-0034](0034-s5-final-stage-separation-and-condition-enumeration.md) 的逐批费用上限；补充批次 1 执行与停止规则的适用范围

## 上下文

ADR-0034 的批次估算小于逐调用最坏预留。按冻结峰值费率，调查调用须预留 ¥2.105344，终裁须预留 ¥2.228224；原 ¥1.5/¥2 批次无法启动。不能用预计输入量降低许可预留。

维护者在 2026-10-13 当前会话明确批准：**“同意各批次 ¥4，累计仍 ¥28”**。这修订逐批许可，不增加调用名单、不重置已花费用，也不代替具体 manifest 的独立放行。

## 决策

1. ADR-0034 的收费批次 1、2、3、4、6、7、8 上限统一为 **¥4**；批次 5 不收费。S5 累计上限仍为 **¥28**。每次发送前同时满足“本批 known+held+下一许可 full hold ≤ ¥4”和“S5 历史及当前 known+held+下一许可 full hold ≤ ¥28”。各批许可之和不是新增消费承诺；实际余量始终来自 PG 累计账本。
2. 批次 1 为原 `adjudication-20261011/seen-v3-agent` 的 20 案，各终裁一次。离线重建原 118 次 v4 chat 的 `parameter_hash`，验证原始来源、marker 边界及调用账本，再用实际 `SupportAgentV5Adapter` 和 `prepare_chat_request` 生成请求。保留已提交 marker 供 adapter 验证，它在生成消息前移除初稿；不补政策，不注入 gold 或旧答案。
3. 复用隔离 `support_diagnosis` Go runner 的 PG 唯一发送权、预留、usage 解析及不可覆盖证据，以 **manifest schema 3** 显式限定 v5 的 20 案一次名单、thinking/high、16,384 completion token、120s HTTP 上限和不发送 temperature。旧 schema 1/2 的名单、费额与请求语义不变。新分支跨账户仍累计本批 ¥4，不能通过另开账户绕过上限。
4. 回放是固定输入的真实模型 HTTP 诊断，**不是生产 Run、IPC v2、调查检索或业务审批验收**。其原始响应和账本按原谓词与 `claim_sources` 离线评分，全部未执行及失败保留在 20 案分母，`thresholds_met=false`。生产执行路径由后续真实回归验证。
5. 批次 1 的两种闭合缺口是旧输入属性，完整报告但不作为“v5 调查再次失败”的停止条件。ADR-0034 的双闭合停止门适用于重新执行调查的批次 2、3、6。回放发生身份、计量、费用、来源或报告绑定异常立即停发；unknown 保留 full hold，不重发。若出现系统性格式失败或投影构造错误，不进入下一批，先诊断。
6. 修复新颖性入口遗漏：schema 13 候选的非历史包加载及直接正式评分均拒绝三个已见 dataset，即使重新绑定冻结摘要和时间也不能转为未见集。原 v1–v3 的 `--seen-diagnostic` 继续可用；不提前创建或绑定新未见集。

## 契约与验证

不改变生产 API、IPC、数据库 migration、状态机、提示词、政策、gold、评分谓词或历史证据。新增工具包和授权回执放在仓库外，源码留在仓库受审；manifest 绑定原始证据、原登记、输入重建证明、工作树源码、runner、当前价格与账本摘要。

免费验证覆盖：原始请求重建、投影无初稿泄漏、来源/请求篡改拒绝、固定名单与参数拒绝、累计 ¥28 和本批 ¥4 的真实 PG 预留守卫，以及 schema 13 已见包复用负例。实际通过项与收费结果另记状态和证据，不由本 ADR 推断。

批次之后追加累计账本；失败不选择性补跑、不扩大名单、不改写原响应。后续开发、冻结、新颖性审查、正式门槛及恢复顺序继续遵循 ADR-0034。
