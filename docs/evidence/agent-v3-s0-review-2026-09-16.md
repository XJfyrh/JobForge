## 契约审查

详细契约已补充以下边界，仍按仓库流程处于 Proposed：

- 行锁取得之后按数据库时钟判断 lease；中间步骤重复提交与释放租约后的只读确认分开。
- 正常审批继续不计故障恢复次数；stopping 的首次原因与后到取消分别保存，取消/总期限阻止再次恢复。
- 订单、工单、物流聚合与政策读取同一不可变快照；新增物流事件也改变写入前置版本。
- 接收端先查相同操作的已提交回执，再验证首次写入条件；批准和重试不延长原许可。
- 人工 retry 遇到已授权但未知的旧动作时只读核对，不重发、续签或换方案；取消不等于业务未发生。
- 物理模型请求次数不因 usage 结算退回；未知完成仍占额度，已知调用审计不能推进终态 Run。

这些是设计审查结论，不能代替真实 PostgreSQL、并发、故障或业务验收。
