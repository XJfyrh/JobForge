# 售后 Agent 的职责与人工边界

JobForge为客服整理证据和建议：读取授权工单快照、关联订单、物流和版本化政策，提出有引用的方案；人工审阅原方案后，才允许记录结论或修改工单标记。

## 一个完整案例

客户询问包裹是否延迟。Agent核对承诺时间、签收事件和政策，给出结论及实际来源。审阅者查看依据，并在批准前确认“保存结论、保留原状态”的影响。批准决定先保存，业务服务随后返回回执；回执确认后页面才显示工单已更新。

[免费体验](quickstart.md)使用确定性响应演示链路；[真实模型结果](evidence/agent-v3-s5-v9-formal-v4-2026-10-16.md)独立记录质量和原始失败。

## 何时需要人

下表为当前政策摘要，实际决策绑定Run捕获的政策版本：

| 情况 | 预期方案 | 依据 |
|---|---|---|
| 已成立的结构化事实冲突 | 升级人工 | [P05](../examples/support-agent/runtime/policies/P05.md) |
| 有效签收记录与未收到、地址或收件人异议冲突 | 升级人工，保留双方证据 | [P04](../examples/support-agent/runtime/policies/P04.md) |
| 当前丢失、损坏或退回，未被有效纠正 | 升级人工 | [P06](../examples/support-agent/runtime/policies/P06.md) |
| 未交付且超承诺至少48小时 | 升级人工；已完成的晚交付不套此条件 | [P07](../examples/support-agent/runtime/policies/P07.md) |
| 缺必要关联、事件或问题描述 | 指明需补充的信息 | [P03](../examples/support-agent/runtime/policies/P03.md) |
| 任意业务写入 | 独立approver批准原方案 | [审批合同](agent-v3/approval.md) |

审阅者核对结论是否符合事实、引用是否支持对应主张；发现错误可拒绝方案。批准通过独立 approver 身份完成。

## 当前动作合同

| 方案或状态 | 实际含义 |
|---|---|
| 保存结论 | 记录支持的结论，保留工单状态 |
| 补充信息后继续 | 保存缺失字段并标记等待补充，由客服联系客户 |
| 需人工跟进 | 保存原因和标记，由客服安排后续处理 |
| 方案已批准 | 已获写入许可，等待业务服务执行并返回回执 |
| 工单已更新 | 回执确认结论/标记已提交，客服继续跟进客户问题 |
| 更新结果待确认 | 按原操作编号查询回执后确认结果 |

客户联系、外部派单、退款付款和工单关闭由客服及现有业务系统完成。工作台中，operator 提交、取消和核对，approver 批准或拒绝，reader 查看。执行与回执机制见[工程亮点](engineering.md)。
