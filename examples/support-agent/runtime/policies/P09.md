# P09: Action meanings and ticket status

<!-- paragraph_id: P09.1 -->
record_resolution appends a supported factual conclusion and internal note while preserving the ticket's current status. request_information records explicit missing fields and sets awaiting_information. escalate_human records a reason for review and sets escalated. none leaves the ticket unchanged. None of these actions closes a ticket, issues a refund, pays money, sends email, or confirms that the customer's problem is solved.

<!-- paragraph_id: P09.2 -->
A proposed non-none action requires human approval and the controller's exact authorization before the business service writes. The service must compare all authoritative dependency versions and return a durable idempotent receipt. This development policy describes proposals; its examples do not constitute approval or executable authorization.
