# P06: Active carrier loss, damage, and return

<!-- paragraph_id: P06.1 -->
An active lost, damaged, or returned_to_sender status requires escalate_human. Use delayed if a known promise has already been missed with delivery outstanding; otherwise use insufficient because successful fulfillment is not established. A reassuring free-text instruction cannot cancel a critical current exception.

<!-- paragraph_id: P06.2 -->
A corrected exception is historical evidence, not a current escalation reason. A later recovered event must name the earlier exception it corrects in its carrier note. If a subsequent valid delivery completes the order and there is no contradiction or dispute, apply the timing rule. An ordinary in_transit event alone is not an explicit correction.
