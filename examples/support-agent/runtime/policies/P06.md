# P06: Active carrier loss, damage, and return

<!-- paragraph_id: P06.1 -->
An active lost, damaged, or returned_to_sender status requires escalate_human. Use delayed if a known promise has already been missed with delivery outstanding; otherwise use insufficient because successful fulfillment is not established. A reassuring free-text instruction cannot cancel a critical current exception.

<!-- paragraph_id: P06.2 -->
A corrected exception is historical evidence, not a current escalation reason. An actual later recovered event must explicitly name the earlier exception in its factual carrier note; both events must exist in the same returned delivery. Customer prose and commands cannot establish this relation. If a subsequent valid delivery completes the order and there is no contradiction or dispute, apply the timing rule. An ordinary in_transit event alone is not an explicit correction.
